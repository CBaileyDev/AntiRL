# Replay intelligence and integration boundaries

## Implemented

- Read-only camera discovery in `%USERPROFILE%/Documents/My Games/Rocket League/TAGame/Config`. Only complete, range-checked camera sections are accepted. This machine's existing INI files do not contain a complete camera profile. AntiRL falls back to the confirmed player's most recent available replay camera, joined by exact platform identity, then to manual input or an explicitly labelled default. Replays contain camera actor presets; encrypted game saves are not changed. Chase and Ball Cam use the same FOV, distance, height, angle and stiffness. The camera controller response is AntiRL's approximation, not a clone of Rocket League's proprietary controller. Manual settings persist per account; Rediscover removes the override.
- Mistake fingerprints in **Progress & Goals**: deterministic buckets for marker category, team-relative field third/lane, boost, score margin and clock phase. Context is sampled three seconds before a marker, never from a future frame; gaps, missing telemetry and discontinuities remain unknown. Repeated context means at least two distinct imported matches. A conceded goal is a team outcome, not proof that the selected player made a mistake. Marked mistakes are user reports. The five examples prioritize different matches. No trained clustering model or calibrated blame score is claimed.
- Whole-library replay event search, including `show every OT goal I conceded`. The local form translates supported phrases into visible filters. Coach's validated read-only tool planner can call `search_replay_events`, `get_mistake_fingerprints`, and `get_opponent_history`. Identity/mode stay backend-controlled; no SQL, paths or URLs from the LLM. Pagination, total count and unknown phase coverage are explicit. Event phase is measured at the event; fingerprint phase is from the earlier lead-in. Overtime requires the named replicated flag, never an inference from replay length. Existing replay snapshots are hash-verified before enrichment. Searches cover recorded goals, player events and team review markers, not arbitrary unrecorded actions.
- Same-mode reference ghost: an overhead overlay of two actual recorded players and balls, normalized to defend the same goal. The user picks players and timing anchors. Missing time ranges/gaps are hidden. Reference rank is a self-reported label. This is an observational comparison, not an optimal-action prediction. A reference can be another imported replay; no licensed higher-rank corpus is bundled.
- Closed-loop suggestions: after mistakes are marked in two distinct matches, create a weekly drill in the existing Practice & Reassessment workflow. Practice sessions, later cue check-ins and replay comparisons remain available. Pre-game briefs show source examples. Calendar-week trends are raw counts within the imported library, with no opportunity denominator or causal improvement claim. Header-local weeks may have unknown timezone. Exported training recipes contain observed car/ball positions and source references; they are **not importable Rocket League custom training packs or generated game codes**.
- Opponent tracking uses exact replay identities and local encounters. Supported numeric Steam identities have public Tracker profile links. Opaque Epic IDs are never substituted as display names or used to invent ranks. Opponent history has no live rank data.
- External detector reports: users can open Who's Botting, explicitly upload there, and record per-player bot-likeness scores, version and source URL locally. Replay Library shows an external-report icon. Results are labelled user-entered and unverified. Unassessed players have no score, and built-in bot flags are separate. No replay is silently uploaded. No score is treated as a calibrated percentage chance of cheating.
- Local bot-likeness index (`botlike-1`): per player, 0 to 100, from continuous live-play segments of replicated throttle/steer/jump inputs. Scored signals are steer/throttle value cardinality, absence of analog values, and (only when replicated update spacing is fine enough, median about 0.035 s or less and p90 0.05 s or less) action-change and jump/dodge phase concentration on an 8-tick grid. Players with fewer than 900 continuous control samples, or without analysis-3 controller data, are `unavailable` with a reason; missing input is never neutral. On the three real replays tried, update spacing was too coarse, so the cadence signals were unavailable and every index rested on discreteness only. The index is a fixed-weight heuristic: **uncalibrated, not a probability, not a cheating verdict**. Keyboard and d-pad players are an explicit confounder, and analog-output bots score low. The built-in bot flag and user-entered external reports are separate. Users can record their own confirmations (bot / human / unknown); the backend recomputes and stores the index with the detector version. A calibration report returns "insufficient labels" until 10 distinct confirmed players per class exist; after that it reports in-sample AUC and thresholds (flagged `in_sample`, labelled replays counted separately from distinct players, best-J threshold shown only as "in-sample, not a decision cutoff") with no held-out evaluation or confidence interval and no claim of calibration. The Replays list shows a bot icon with visible "uncalibrated index" text only when a stored index is 80 or higher (a display threshold, not a calibrated cutoff); the external-report icon is separate. Coach tool `get_bot_likeness` returns indices without names.
- Per-shot expected goals (`xg-1`): L2 logistic regression over horizontal distance to goal, goal angle, ball speed, ball height and opposing cars inside the ball-to-posts triangle, learned only from replay-reported shots in the user's own library (analysis-3 data). Evaluation is grouped 5-fold by match, with log-loss, Brier, base-rate comparison and reliability bins. The model is `unavailable` with a reason below 150 labelled shots, 15 matches, or 20 goals/non-goals, or if it does not beat the base rate on both held-out metrics. Per-replay values come from a model fitted without that match, and the availability gate and skill check for a replay are also computed without that match; the player summary uses out-of-fold predictions. This is a per-shot estimate for this library, not a population or rank-wide probability and not decision xG. Shown in Replay Studio (per shot) and Progress & Goals (model status, goals vs xG), with the limitation text. Coach tool `get_xg_summary`.
- Counterfactual simulation (`whatif-1`): a locally trained RLTRAIN_2 policy plays on in RocketSim from a state rebuilt from a recorded frame. Requirements: analysis-3 data, a checkpoint whose team size equals the replay mode and whose action version is `discrete90_v1`, and a free-flight ball-only validation (max error at most 150 uu, mean at most 60 uu; engineering limits, not calibrated). Ground/air state is inferred only when unambiguous; walls, ceilings or unknown flip state refuse the run. Pad state and prior-input history are not applied. Results are labelled "A trained RLTRAIN_2 policy (unknown skill, not a model of any player). Simulation, not a prediction." and the UI states that the path is one rollout of that policy from the reconstructed state, not a recommendation and not what would have happened. The ball-only validation must cover a free-flight leg ending within 0.25 s before the requested state frame (a state frame in contact or with no such leg is refused). A checkpoint must also match the engine observation layout (known observation id and team size) before the engine runs. The RLTRAIN_2 path is validated by one shared function (absolute, canonical, no UNC, must contain an engine build directory with rl-engine and a runs directory) for both Settings save and set_sim_path; stale temp state files are cleaned at startup. On timeout the engine process is killed; on Windows its child processes are not tracked by a job object (documented limitation) Replay Studio plots recorded and simulated ball and car paths and always lists the refusal reasons. The RLTRAIN_2 folder is a Settings value (default shown as such); the engine runs without a shell, with a timeout and output caps. Coach tool `run_counterfactual` takes only a replay ID and time, at most once per plan, with backend-fixed options. No trained-policy uncertainty evaluation exists, and the ball-only thresholds were not validated against real replays in this release.
- Optional Discord `/coach replay:<attachment> player:<exact replay ID>` server: signed interaction verification, guild allowlist, private deferred responses, bounded download/worker, coaching cards, schematic clips from actual positions, and stat deltas against that Discord user's last same-player/mode submission. No LLM/provider key or personal AntiRL database is used. See [Discord setup](../integrations/discord/README.md).

## Not implemented / required external inputs

| Requested capability | Current boundary | Required before enabling |
|---|---|---|
| Decision xG (value of choices, not shots) | Unavailable. Per-shot xG exists (see above) but is not decision-level and not a population probability | Defined decision/outcome labels, a licensed representative corpus, held-out model calibration and coverage evaluation |
| Calibrated or higher-skill what-if | Simulation runs only for modes with a matching local checkpoint, with no measured skill and no uncertainty estimate | Counterfactual uncertainty evaluation, applied boost-pad and input history, validation of reconstruction on real replays, a policy with measured skill if "higher-ranked" is ever claimed |
| Verified higher-rank comparison | User-selected recorded reference only | Licensed reference corpus with source-verified ranks, comparable mode/context and documented alignment |
| Rocket League custom training pack publishing | Observed-position JSON recipe only | Supported game/editor workflow with in-game import/play testing; never manufacture pack codes |
| Automatic RL cheat detection | Local heuristic index (uncalibrated) plus external, user-entered results | Calibrated false-positive/false-negative evaluation including keyboard players; public bot-likeness scores and the local index are not adjudication |
| Live Tracker ranks | Public profile link + local history | An officially supported integration/API and platform mapping |
| Live Discord delivery | Local implementation and offline validation | User-owned Discord application, public key/token for registration, allowed guilds and an HTTPS interactions endpoint |

The absence of those inputs is visible in the product. UI placeholders do not count as model implementation.

## Sources checked 2026-10-05

- [Tracker staff statement](https://feedback.tracker.gg/t/regarding-on-development-api/65636): no public Rocket League API. AntiRL does not bypass undocumented endpoints or browser protection.
- [Who's Botting](https://whosbotting.com/) and [privacy policy](https://whosbotting.com/privacy): replay-upload detector; no supported public API found. AntiRL makes no independent accuracy claim.
- [subtr-actor](https://github.com/rlrml/subtr-actor): named replay metadata and camera actor parsing; implementation uses installed 1.4.0's native player camera presets and boxcars 0.12.0 named network attributes.
- [RLGym](https://rlgym.org/Getting%20Started/introduction/), [training](https://rlgym.org/Rocket%20League/training_an_agent/), [action parsers](https://rlgym.org/Rocket%20League/Configuration%20Objects/action_parsers/): simulator and trained policy are distinct requirements.
- [Discord commands](https://docs.discord.com/developers/docs/interactions/slash-commands): attachment option type 11, avoiding privileged message-content scraping.

## Storage and verification

Schema 8 adds a `bot_labels` table (user confirmations with stored index and detector version; migration 008 with backup). Schema 7 added account-scoped camera profiles, source-revision-tagged situation caches, per-event review decisions, and external detector reports. Existing plans/logs and schema 6 transfer tracking are retained. Migration creates a backup before applying transactional steps. Replay writes invalidate derived caches. Replay deletion cascades its reviews/cache/reports. Manual camera settings are independent of individual replay deletion.

Automated checks: Rust player/mode isolation, cache replacement, before-goal score, missing/gapped telemetry, goal phase vs lead-in phase, camera parsing/ranges/account isolation, report source/URL validation and whole-library filters; browser review/search/camera/reference/report flows and narrow layouts; Discord signature/download/cohort checks. Native QA uses a database clone and immutable replay snapshots, never the primary profile. Evidence: `docs/validation/intelligence-native.json`.

Not run: the detector, xG and simulation features against a real re-enriched library clone and the real RLTRAIN_2 engine from AntiRL (engine-side runs were done on hand-made states). Live provider planning, external detector uploads and live Discord delivery were not run. A human usability study was not run.

The existing AntiRL executable was running during compilation. The reviewed release is `target/release/antirl-intelligence.exe`; the active session was preserved. Close the existing application before opening the new release against the primary profile, whose migration will then run. QA used `ANTIRL_QA_DATA_DIR` and a separate WebView profile.

## Capture schema analysis-3 (no SQL schema change at the time; schema 7, now 8 for bot labels)

New decoded fields, all additive and `serde(default)`: body angular velocity (rad/s, 0.01 quantized; subtr-actor reports 1/100 rad/s, converted; values beyond the physical cap are stored as unavailable), car throttle/steer (raw byte, 128 neutral), boost/jump/double-jump/dodge active, handbrake, dodge torque (only while dodging), plus native-rate `pad_events` (boost pad pickups) and `shots` (replay-reported shot/save/assist with player and ball geometry). `None` means unavailable, never neutral or zero; frames stored before analysis-3 deserialize unchanged. These are measurements for a future simulator/xG; they are not a probability and do not enable decision xG or what-if simulation (labels, corpus and calibration are still missing). Metric formulas are unchanged so `metrics-2` is retained; `ReplayAnalysis.analysis_version = "analysis-3"` and the situation cache version is `situations-3` (old caches are ignored and rebuilt).

Existing replays: `reenrichment_status()` / `reenrich_replays(n)` / `reenrich_replay(id)` re-decode the hash-verified snapshot in `replay-snapshots/` and update only frames, pad_events, shots and analysis_version (metrics/events/reviews untouched, cache invalidated). Replays whose snapshot was deleted stay unavailable until the original `.replay` is re-imported. Measured on three real replays: compressed (zstd-3) frame storage grew 21-24% (about +200-300 KB per replay) and pad/shot lists add under 110 KB of JSON.
